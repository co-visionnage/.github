# .github организации co-visionnage

Репозиторий-«витрина» организации. GitHub использует его файлы **по умолчанию**
для всех репозиториев организации, в которых нет своих:

| Файл | Что это |
|---|---|
| `SECURITY.md` | как сообщить об уязвимости |
| `CONTRIBUTING.md` | как вносить изменения |
| `CODE_OF_CONDUCT.md` | кодекс поведения |
| `SUPPORT.md` | куда обращаться за помощью |
| `ACCESSIBILITY.md` | наше обязательство по доступности и известные ограничения |
| `.github/ISSUE_TEMPLATE/*` | формы issue: ошибка, идея, барьер доступности |
| `.github/PULL_REQUEST_TEMPLATE.md` | шаблон pull request |
| `profile/README.md` | страница организации |

Если в репозитории есть собственный файл с тем же именем, используется он, а
не этот. Репозиторий должен называться ровно `.github` и быть публичным.

## Что нужно включить в самих репозиториях

Эти настройки в организации по умолчанию не включаются:

- **Private vulnerability reporting**: Settings → Code security → включить в
  каждом репозитории, иначе кнопка «Report a vulnerability» из `SECURITY.md`
  не появится.
- Метку `accessibility` (форма «Барьер доступности») и `question` создайте в
  Issues → Labels; `bug` и `enhancement` есть по умолчанию.
- Защита ветки `main`: обязательные проверки CI и pull request.
