# Как внести вклад

Спасибо, что хотите помочь. Этот файл действует для всех репозиториев
организации, если в репозитории нет своего `CONTRIBUTING.md`.

## Из чего состоит проект

| Репозиторий | Что это |
|---|---|
| `co-visionnage-app` | Фронтенд (Next.js, TypeScript) |
| `notrecinema-api` | HTTP API (Go) |
| `notrecinema-worker` | Воркер: письма и push (Go) |
| `database` | Схема БД, миграции (единственный источник истины) |
| `notrecinema-infra` | Развёртывание сервера (Ansible) |

Фронтенд общается только с API, API и воркер — с базой. Правила доступа к
данным живут в БД (RLS), поэтому изменение схемы почти всегда затрагивает
несколько репозиториев.

## Прежде чем начать

- Для крупных изменений сначала откройте issue и обсудите идею.
- Ошибки и предложения оформляйте через шаблоны issue.
- Об уязвимостях сообщайте закрыто — см. [SECURITY.md](SECURITY.md).

## Рабочий процесс

1. Создайте ветку **от актуального `main`**: `git switch -c feat/короткое-имя origin/main`.
   Ветка `main` защищена, напрямую в неё не коммитим.
2. Делайте небольшие коммиты в формате
   [Conventional Commits](https://www.conventionalcommits.org/ru/) (в репозиториях
   настроен `cz-conventional-changelog`): `тип(область): описание`, например
   `fix(ci): run migrations before the api in e2e`.
   Типы: `feat`, `fix`, `docs`, `refactor`, `test`, `chore`, `ci`.
3. Перед пушем запустите проверки своего репозитория (ниже).
4. Откройте pull request в `main`. Заполните шаблон: что и зачем сделано, как
   проверить.
5. Дождитесь зелёного CI и ревью. Мы сливаем через **Squash and merge**, поэтому
   название PR должно быть хорошим сообщением коммита.

Если ваша ветка отстала от `main`, подтяните его (`git merge origin/main`) и
разрешите конфликты. Не коммитьте маркеры конфликта (`<<<<<<<`).

## Проверки по репозиториям

**co-visionnage-app**
```bash
pnpm install --frozen-lockfile
pnpm exec tsc --noEmit
pnpm exec eslint .
pnpm test
pnpm test:e2e      # нужен Postgres, NATS и соседние репозитории, см. README
```

**notrecinema-api / notrecinema-worker**
```bash
go vet ./...
go test ./...
DATABASE_URL=... go test -tags integration ./...   # нужен Postgres со схемой
```

**database** — миграции идемпотентны (`IF NOT EXISTS`, `CREATE OR REPLACE`),
нумерация следующая по порядку (`NNNN_название.sql`), правила доступа задаются
RLS-политиками.

**notrecinema-infra**
```bash
yamllint --strict .
yamlfmt -lint .
cd ansible && ansible-playbook site.yml --syntax-check
```

## Порядок слияния при изменениях в нескольких репозиториях

1. `database` (миграции) — первым: интеграционные тесты и e2e других
   репозиториев берут схему из `main`.
2. `notrecinema-api` и `notrecinema-worker`.
3. `co-visionnage-app`.
4. `notrecinema-infra`.

В описании PR укажите связанные PR в других репозиториях.

## Требования к изменениям

- Новое поведение покрыто тестами; ошибка сначала воспроизводится тестом.
- Секреты, ключи и пароли не попадают в код, примеры `.env` и логи. Для
  примеров используйте пустые значения или явные заглушки.
- Зависимости обновляет Dependabot (минорные и патчи — сгруппированно). Если
  обновление ломает сборку, исправьте код в отдельном PR.
- Пользовательские тексты — на русском, код и сообщения коммитов — на английском.
- Следите за доступностью интерфейса: подписи у полей и кнопок, клавиатурная
  навигация (см. [ACCESSIBILITY.md](ACCESSIBILITY.md)).
